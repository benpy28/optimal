- OptimalFS: an operation that fails part way (a read error or a bad checksum in the middle of a rename, unlink, write, truncate or snapshot operation) is now undone in memory before it returns its error, and the volume stays writable; before, it stopped all writes until a remount. The trees log each item they change with its old value (moved, not copied), so the cost on the success path is within run-to-run noise (20000 creates, writes, renames and unlinks, with and without commits, against main). A commit that fails while building file extents or appending to a snapshot deadlist is undone the same way and retried, and a bad checksum on a read inside a commit is retried, degrading the volume if it persists. A superblock slot whose write fails is written around for the rest of the mount: every commit still lands on two slots, one per flushed wave, and with fewer than two working slots the volume degrades instead of overwriting its last copy in place. New tests fail every read point of every operation of random workloads (as an I/O error and as damaged data), kill superblock slots for good, and check fsck after every undo.
