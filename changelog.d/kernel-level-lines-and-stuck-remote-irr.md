- The kernel now ends level-triggered interrupts at the I/O APIC itself and clears a stuck Remote IRR (Phase 1c, step 1c3c). EOIs are directed (SVR bit 12 set, the vector written to the I/O APIC's EOI register) when the local APIC can suppress broadcasts and every used I/O APIC is version 0x20 or later with its EOI register inside its mapped page; otherwise they are broadcast, and the boot log's new `eoi:` line says which and why. Directed EOI matters once vectors are allocated per CPU: a broadcast from one CPU can clear Remote IRR on a pin aimed at another CPU that uses the same vector.
- Level lines (`irq::level`): a GSI the routing plan leaves free, or a level-triggered ISA IRQ such as the SCI, is claimed with a handler and held masked from the interrupt until the handler says it is done, so a device that keeps asserting its line cannot storm the CPU. Unmasking reads the entry first; a Remote IRR still set (an EOI that named another vector, or a local APIC that took the interrupt as edge) is cleared by the EOI register where there is one, else by the trigger toggle (mask, edge, level), and a pin neither clears is left masked and reported stuck. Setup does the same for every pin firmware left with Remote IRR set. Every refusal has a name (not a device vector, vector or pin busy, a GSI the plan uses, no I/O APIC, an edge ISA IRQ). Cost per level interrupt: one I/O APIC write to mask, one read and one write to unmask, and the EOI register write in directed mode; MSIs need none of it. `isa_unmask` now refuses a level-triggered ISA IRQ.
- `optimal-apic` gains the EOI rule and the Remote IRR recovery sequence, tested against a model pin (EOI register and toggle that work or not, clears that show late) over random entries: every write but the last keeps the pin masked, the EOI register gets the vector the entry has now, and the outcome is the one the pin calls for. `optimal-time` gains HPET comparator routing for level one-shot interrupts and the comparator and input choice. Mutation testing: 0 missed in both.
- Kernel tests drive an HPET comparator as a level device on a free I/O APIC input (GSI 16 on QEMU's q35): 26 interrupts each arriving once, seen in the handler with the pin masked, Remote IRR set, the vector in service and its TMR bit set; a held line staying masked while the device asserts and re-delivering on done; a Remote IRR made stuck by moving the entry's vector while in service, cleared by the expected method; and a pin that will not clear (modelled) left masked and refused until it does.
- Tough conditions: the EOI register (QEMU's I/O APIC), the trigger toggle (QEMU's I/O APIC as version 0x11, and KVM's in-kernel one), directed EOI under KVM with a split irqchip, and QEMU's pc machine, where the HPET reaches no free input (and, given GSIs 16 to 23, where it does).
- CI: the runner's NTP daemon is stopped before any QEMU run (scripts/steady-host-clock.sh). QEMU drives the guest's HPET from the host's NTP-steered monotonic clock but the guest's TSC from the host's TSC, so while the host slewed, the two disagreed by tens of ppm, which made 3 of 1207 nightly soak boots fail their clock checks on 27 Nov 2026.
