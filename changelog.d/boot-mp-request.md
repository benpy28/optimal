- Optimal Boot: the MP request. The loader starts every enabled processor in the MADT, one at a time after leaving the firmware, and parks it in the handoff page until the kernel writes its `goto_address`. Each AP gets the BSP's page tables, control registers, PAT and MTRRs, a GDT and stack of its own, and from base revision 5 the same local APIC set-up as the BSP. x2APIC is turned on when the kernel asks and the CPU has it. If the firmware left it on and it cannot be turned off, the boot is refused, as the protocol requires. The conformance kernel now makes the MP request in every case and checks each AP's state; new cases `smp-r3` and `smp-x2apic` (needs KVM).
