- Timer events now fall back past the local APIC timer (Phase 1c, step 1c3d1), completing ROADMAP 1c's order: TSC-deadline mode, then LAPIC one-shot, then an HPET comparator, then the PIT. The fallbacks are set up, and their rates measured against the clock (to 100 ppm, at most 50 ms, as for the LAPIC timer), only when neither LAPIC mode can be used. The `timer:` boot line names the source and its rate, and says `the clock itself` when the HPET is also the clock (then its rate is exact, not measured).
- HPET events: a comparator in one-shot, edge-triggered mode on an I/O APIC input the routing plan leaves free (the highest-numbered comparator that reaches one, on its lowest such input: comparator 2 on GSI 16 on QEMU's q35), on vector 0xED. `irq::level::claim_edge` claims such a GSI under the same rules as a level line. Arming reads the counter, writes the comparator, reads the counter again, and if the counter got there first (a comparator matches only on equality) moves it 2 us further ahead, then 4, 8 and so on, up to 16 times; the comparator's interrupt is enabled after the first write, because QEMU fires a passed comparator the moment its interrupt is enabled. One arming covers at most 2^31 - 1 ticks on a 32-bit comparator (21.4 s at 100 MHz) and 2^62 on a 64-bit one; longer waits are reached in pieces.
- PIT events: channel 0 in mode 0 on ISA IRQ 0, armed with the mode and the count's two bytes (three port writes), at least 1 and at most 65,536 periods (54.9 ms), measured on channel 2. QEMU's PIT keeps counting through a mode write (the 8254 datasheet says the write resets it), so a count armed before a switch away from the PIT can still raise one edge; IRQ 0 is masked while the PIT is not the source.
- Never early, as before: every source rounds its count up at the fastest rate its bound allows, plus its own phase uncertainty (one tick for the HPET's counter read; the PIT's load on the next CLK already gives N whole periods), and the handler checks the clock before running the hook. The early-interrupt count excludes the interrupts the hardware may legitimately send before the deadline: after a comparator retry, after a 64-bit comparator write whose high half changed (QEMU splits it into two 4-byte writes, low half first), and on a 32-bit comparator armed across the counter's 32-bit wrap (which interrupts too, IA-PC HPET 1.0a 2.3.9.2.1).
- `notimer=` (words `lapic`, `hpet`, `pit`) rules sources out, as a quirk switch and to test the fallbacks.
- `optimal-time` gains `oneshot` (HPET and PIT tick counts, the longest arming, the comparator programming loop against a model comparator, and when an early interrupt is possible) and `select::events` over all four sources. Hand-worked cases (1 ms at 100 MHz is 100,001 comparator ticks; 54,925,409 ns is the PIT's longest arming at 13,125,000/11 Hz), property tests against exact arithmetic and a counter that moves between reads, and mutation testing with 0 missed (5 mutants of the binary search time out, which counts as caught).
- Kernel tests force every source the machine has in turn and check each never fires early (on the clock and on the reference read independently), in whole armings and in 3 ms pieces, with cancel, past and replaced deadlines; PIT timers of 60 and 150 ms take several armings; the refinement moves the HPET's and the PIT's rates with the clock; every source the tests set up is given back. Tough conditions add HPET and PIT events (q35, UEFI, TCG with 4 CPUs, no HPET with the PM timer as the clock, QEMU's pc machine, where the HPET reaches no free input and the PIT takes over with a warning), HPET events timed against a TSC clock with the refinement and with the watchdog falling back.
