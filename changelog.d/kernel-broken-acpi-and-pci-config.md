- Tough-conditions runs now boot the kernel on firmware whose ACPI tables have been broken in RAM just before the kernel starts: wrong MADT and FADT checksums, a broken XSDT signature and a broken RSDP extended checksum (both must fall back to the RSDT), junk in the first MADT (a duplicate APIC ID, the broadcast ID 0xff and a zero-length entry), an HPET table with a misaligned register address, FADT DSDT and X_DSDT fields that disagree, and a DSDT pointer into PCI configuration space. Each break runs alone and all of them together (two combinations, on every fetched OVMF build), and every run must print exactly the expected `acpi:` summary and warnings. The breaks come from new `acpi-*` words in the firmware-quirk injector (bootloader/quirk, test only), applied after ExitBootServices so no firmware code can repair them, and booted from UEFI disk images made by `scripts/quirk-image.sh`.
- The kernel's ACPI reader now refuses PCI Express configuration space (ECAM). Firmware memory maps call it reserved, so the memory-map check alone allowed it: the new DSDT-pointer test showed the kernel reading PCI configuration registers on both OVMF and SeaBIOS. The MCFG is now read first and every range it lists is refused for every later read. A new host-tested MCFG parser (`optimal_acpi::mcfg`) refuses only the listed buses of a valid entry and all 256 buses of a malformed one, checked against a model with random tables, and a new kernel test checks the refusal on the real machine.
