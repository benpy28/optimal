- The kernel now reads the firmware's ACPI tables at boot (Phase 1c part 2). It gets the RSDP from Limine, copies every table (and the DSDT the FADT points to) into the kernel heap, parses the MADT, HPET table and FADT, and prints one `acpi:` summary line (root table, tables found, CPUs enabled, off and hot-add, I/O APICs, overrides, HPET, PM timer, memory reclaimed) plus one line per firmware mistake it worked around.
- Firmware memory is read only where the memory map says firmware data lives (ACPI reclaimable, ACPI NVS and reserved entries, and gaps in the legacy BIOS area). Free RAM, the kernel, the APIC and HPET register window, and reads that wrap are refused, so a corrupt table address can't make the kernel read its own memory, poke a device or fault. Pages outside the direct map are read through a one-page, read-only, uncached window that is unmapped straight after. The rules live in a new host-tested module, `optimal_acpi::reach`, checked against a byte-level model with random memory maps.
- Once the tables are copied, ACPI reclaimable memory goes to the frame allocator, except the FACS's pages, which firmware and OS share.
- The FADT parser now also returns the DSDT and FACS addresses (the X_ fields win, and a clash with the 32-bit fields is reported).
- New kernel tests check the reader's refusals, reads across page boundaries against the copies, the boot CPU in the MADT, whole table copies, and that the reclaim adds exactly the ACPI reclaimable pages. Tough-conditions runs now check each machine's ACPI line, and new quirky-ACPI runs add a duplicate junk MADT, unknown signatures, 40 extra tables and a 64 KiB table with `-acpitable`.
