Browser engine: selector matching in `optimal-selectors` now costs time linear in the tree's size on long sibling runs and deep ancestor chains. Within one query (or a new `MatchSession`, which shares the work across many elements), it caches each element's index among its siblings (overall, by type, and among those matching an `of S` argument) and the outcome of each descendant or subsequent-sibling search, so `~`, `:nth-child()`, `:nth-last-child()`, the `-of-type` pseudo-classes and descendant chains no longer look at every earlier sibling or ancestor for each element. A scaling test times these on runs of up to 320,000 elements, in tree order and in reverse, and the random-tree comparison with the literal model now also matches through shared caches in shuffled orders. `:has()` is not cached yet.
