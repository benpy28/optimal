- OptimalFS: a commit whose writes fail no longer stops the volume. The blocks that failed (with their 256 KiB group) are never used again on that mount, the in-memory state is rebuilt on top of the last commit from a log of the transaction's space-map changes, file data that did not reach the disk goes back into memory, and the commit runs again with new homes, at most 3 attempts per commit. After a failed flush, file data written since the last good flush is read back and checked before it is trusted. A device that keeps failing degrades the volume instead: reads work, the changes stay in memory, new changes are refused with a named error until a commit succeeds. A full flush of dirty data inside a write no longer turns a write error into a lost write. New tests fail every write and every flush of random workloads, cut power while a failed commit is retried, kill the device and bring it back, and lose the device cache on a failed flush.
